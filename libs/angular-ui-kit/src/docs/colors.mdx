## Semantic ink tokens

Use these for text instead of the raw scales: the `--color-primary-*` and
`--color-neutral-*` custom properties **invert** in the dark palette, the
semantic tokens are tuned per palette. Ratios are WCAG contrast on the page
background (`--color-background`) / on a card (`--color-surface`); in light both
are white since 3.3. "Worst case" is the lowest ratio over every "Weite"
surface (sky, soft fills, muted tile, land, selected pill; see below).

| Token | Light | Dark | Use |
|---|---|---|---|
| `--color-text-primary` | `#111827` — 17.74:1 (worst case 15.25:1) | `#f1f6f8` — 17.29:1 / 15.85:1 (12.63:1) | body text, headings |
| `--color-text-secondary` | `#4b5563` — 7.56:1 (6.50:1) | `#c4d2d9` — 12.17:1 / 11.16:1 (8.89:1) | secondary text **and small links** (footer, nav) |
| `--color-text-tertiary` | `#5c6672` — 5.84:1 (5.02:1) | `#93a4ad` — 7.31:1 / 6.71:1 (5.34:1) | meta text, on every surface. Since 3.3; it was `#6b7280`, which failed on the light page and the tints (4.16–4.44:1) |
| `--color-link` | `#1a6a79` — 6.21:1 (5.34:1) | `#a3d5df` — 11.78:1 / 10.81:1 (8.61:1) | links in running text — **always underlined** (color alone fails WCAG 1.4.1) |
| `--color-link-hover` | `#144f5b` — 9.13:1 | `#c1e3e9` — 13.84:1 / 12.69:1 | hovered links |
| `--color-overline` | `#144f5b` — 7.85:1 worst case | `#84c7d4` — 7.27:1 worst case | the line above a title (a date, a section name); see `.lc-overline` |
| `--color-on-surface-selected` on `--color-surface-selected` | `#144f5b` on `#e0f1f4` — 7.85:1 | `#a3d5df` on `rgba(32,132,151,.24)` — 9.00:1 (8.14:1 over a card) | the current navigation item and its pill |
| `--color-on-primary` on `--color-primary-fill` | `#ffffff` on `#1a6a79` — 6.21:1 | same — 6.21:1 | primary buttons, the focused skip link |

The ratios are checked by `src/styles/theme-contrast.spec.ts` against the compiled themes.

### Ink on the status tints

`--color-on-{primary,success,warning,error,info}-subtle` on the matching
`--color-*-subtle` tint reach 4.5:1 over every surface (badges, alerts). Since
3.3 the light warning ink is `#855a22` (5.52:1; `#9b6b2b` was 4.25:1) and the
dark success ink is `#a9bb93` (at least 5.17:1; `#8ea475` was about 4.4:1 on a
card).

## Themes: light, dark and following the OS

The palette is chosen by a class on `<html>`:

| Root class | Palette |
|---|---|
| none | dark (Design System 2.0 is dark-first) |
| `dark` | dark |
| `light` | light |
| `system` (since 3.3) | follows the OS through `prefers-color-scheme` — light or dark from the first paint, **no script, nothing stored**; switches live when the OS setting changes. Adds `color-scheme: light dark`, so the browser's own controls follow too |

`ThemeService` mirrors a `system` root (`currentTheme`, `isDark`, the meta
theme-color) without adding a class; `setTheme()` replaces `system` with the
chosen class. For the browser bar without JavaScript, give the page two meta
tags: `<meta name="theme-color" content="#ffffff" media="(prefers-color-scheme: light)">`
and `content="#0a121b"` for `dark`.

## "Weite": the app look (3.3)

A white sky, cards on it with a teal hairline, soft tinted cards for the next
step, and one decorative horizon closing a page. Teal is the only action
colour; member colours appear only on avatars.

### Page sky

Apply the sky on the app shell or `<body>` with **two** properties (the dark
value is a list of layers):

```css
body {
  background-color: var(--color-background);
  background-image: var(--app-background-image);
}
```

## Member colours

One colour per household member, assigned in join order and stable while the
person is a member: `--color-member-1` … `--color-member-6`, the same in both
themes, with **white initials** (`--color-on-member`). Colour is never the only

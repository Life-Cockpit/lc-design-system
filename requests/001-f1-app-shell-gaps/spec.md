## Need

The page is life-os feature F1, the LifeCorner app (sign-in, Today, household, settings). It is an Angular 22 app, prerendered as a static shell behind CloudFront and hydrated, with the kit at 3.3.1. Its build (tasks T117, T116 e2e, T319) is blocked by four kit problems. None of them has an interim the life-os owner accepts (life-os plan decisions B12, B26 and B27, 2026-10-16/17; app-shell concept §7.1).

1. **AS-12: the loading state can't be announced.** On the first load, at every width, the prerendered shell shows Today's skeleton (app-shell 6.6), and the concept wants `<main aria-busy="true">` around it. `lc-app-page` renders that `<main>` itself and passes no attribute through. The app can't mark it without reaching into kit DOM, and the owner ruled that out (B12: "no interim"). life-os already has the test waiting: `libs/ui/shell/src/shell.component.spec.ts:1201` reads `busy` from `AppPageComponent` as a signal and expects `aria-busy="true"` on `<main>` while the skeleton shows, and no `"true"` afterwards.
2. **AS-14: no page with an icon renders under the app's CSP.** ADR-0034 sets `require-trusted-types-for 'script'; trusted-types angular sw-registration`, with no `angular#unsafe-bypass` and no `'allow-duplicates'`. The amendment of 2026-10-17 (B26) adds exactly one name for the kit, `lc-icon`, with the rule that it "accepts only the SVG strings the kit ships with (no consumer input, no unsafe-bypass)". `lc-icon` parses SVG with `DOMParser.parseFromString(<string>)`, which is a Trusted Types sink, and renders it through `bypassSecurityTrustHtml` → `[innerHTML]`, which needs `angular#unsafe-bypass`. So every page with an icon breaks, and every e2e test fails. The life-os violation listener (`apps/cockpit-e2e/src/support/security-listeners.ts`) fails a test on any `securitypolicyviolation` event and also on any console message matching `/Content[- ]Security[- ]Policy|Trusted ?Type|TrustedHTML|TrustedScript|require-trusted-types-for/i`. Every icon F1 uses is inline in the kit: `home`, `sun`, `user`, `key`, `clock`, `light-bulb`, `arrow-path`, `shield-check`, `info-circle`, `plug-connected`, plus the kit-internal `logout`, `chevron-down`, `x-mark` and others. life-os serves no Tabler assets.
3. **AS-15: initial JS is over budget.** ADR-0012 (mobile first) sets a budget of 150 kB gzip / 500 kB raw. life-os measures 198 kB gzip / 766 kB raw, and 238 kB gzip after US1. The kit is one FESM file (`fesm2022/lifecorner-angular-ui-kit.mjs`: 2.32 MB raw, 330 kB gzip unminified, local 3.3.0 build). esbuild assigns each file to one chunk, so every kit part the app uses anywhere lands in the chunk the initial route loads, and lazy routes can't take kit code with them. `ICON_NAMES` (about 5,000 names, 70 kB of source, 18.7 kB gzip as life-os measured it) is in that chunk too, although F1 never fetches an icon. life-os has already cut its own costs (B21: no runtime imports from `contracts`; B35d/e: ports per area, no barrels in the initial chunk). The rest is the kit.
4. **AS-16: the start page isn't announced as current in the side navigation.** On desktop (≥ 1024 px, docked `lc-sidenav`), on `/` (Today, where the app always opens), the Today link looks current but has no `aria-current="page"`. On `/household` it works. The life-os e2e test B[15] ("exactly one `a[aria-current]`", app-shell §7 and §11) fails, and so do WCAG 1.3.1 and 4.1.2. `lc-bottom-nav` on phones is fine.
5. **AS-13: every consumer must resolve `mermaid`.** The FESM file contains a literal `import("mermaid")`, which is `lc-markdown`'s lazy diagram loader. Bundlers resolve it at build time, so an app without the optional peer can't build unless it marks the package external. life-os builds with `externalDependencies: ["mermaid"]`. B12 couples this fix to AS-12's release ("together with the `mermaid` import fix").

The requester also asks for the MCP docs and the changelog to be updated, and for the published version to be reported to the session `life-os-d4 [fc8635]` (by its ref, because another session has the same name).

## Scope

- **In:**
  1. AS-12: `lc-app-page` `busy` → `aria-busy="true"` on its `<main>`, with docs and a story.
  2. AS-14: `lc-icon` renders through one Trusted Types policy, `lc-icon`, that accepts only the kit's bundled SVG constants. There is no `bypassSecurityTrust*` and no string-fed sink, and it works with and without Trusted Types and on the server. Fetched icons keep working, without the policy. Add a browser check under an enforcing CSP.
  3. AS-15: secondary entry points for every component or small group, with no duplicated module and the primary entry unchanged; `ICON_NAMES` out of production bundles unless the app imports it. A fixture proves the split and measures it.
  4. AS-16: `lc-sidenav` puts `aria-current="page"` on exactly the current link, steadily, and the look and the announcement agree.
  5. AS-13: an app that doesn't import `lc-markdown` (or a component built on it) builds without `mermaid`. This falls out of AS-15's entry isolation.
  6. Docs: the MCP getting-started page (import paths, the CSP line, `mermaid`), the import path in every component's MCP entry, `lc-icon` (Trusted Types), `lc-app-page` (`busy`), `lc-sidenav` (current item), both READMEs, the changelog.
- **Not in (non-goals):**
  - Making `lc-markdown`, `lc-code-block`, `lc-log-viewer`, `lc-rich-text-editor` and `lc-document-viewer` work under Trusted Types. The docs list them as needing `angular#unsafe-bypass`. A later request.
  - Icons built entirely from DOM APIs without any sink. ADR-0034 calls this "a later kit option".
  - Shrinking or splitting the inline icon sets. They are what renders offline and in prerendered HTML.
  - A loading text, spinner, `inert` or visual change in `lc-app-page`. The app keeps its own visually hidden status.
  - Removing `lc-icon`'s dependency on `HttpClient`.
  - Any change to `lc-bottom-nav`.
  - life-os's own budget total. life-os checks it in T319; the kit proves its part with a fixture (AC-17, AC-18).
  - A WebKit run under Trusted Types. ADR-0034 keeps it "Unverified"; it is life-os's iPhone e2e.
  - Splitting this into several releases. The requester asked for one.

## Constraints

- The peer range `^21.0.0 || ^22.0.0` is unchanged, and `mermaid` stays an optional peer.
- No new runtime dependency: no Trusted Types polyfill and no `trusted-types` package. Declare the few types needed locally, as life-os did in `sw-registration.ts`. Avoid new dev dependencies too: the browser check uses the CDP pattern of `story-shots.mjs`, and CI may install chrome-headless-shell at run time.
- No API break. The policy name is exactly `lc-icon` (life-os's CSP). The input name is exactly `busy` (life-os's test).
- Nothing in the kit touches `window` or `trustedTypes` at import time; everything is feature-detected (SSR, Angular 21).
- On the success path the kit logs nothing that matches life-os's violation pattern.
- The package stays one npm package built by `@nx/angular:package` (ng-packagr `~22.2.4`). `publish-npm.yml` publishes `dist/libs/angular-ui-kit` as before.
- Story IDs stay stable, because the MCP and the docs link to them.
- No interim on the consumer side is assumed. life-os's T319 adds `lc-icon` to its CSP and switches to secondary entries once the release is out.

## Assumptions

- Assumption: **AS-13 is in scope.** The requester marks it optional, but the life-os owner's decision B12 says "together with the `mermaid` import fix". It is closed through its own entry point (AC-26), not through a non-literal `import()`. A non-literal specifier is left to the browser as a bare `mermaid` and fails at run time, so diagrams would break for every consumer who has `mermaid` installed, which is an API break. The primary entry keeps its 3.4.1 behaviour (AC-27).
- Assumption: **"the kit's bundled icons" means the SVG strings in the kit's JavaScript**: the hand-picked inline set, the inlined Tabler set and the placeholder. The files under `/tabler-icons/` come from `@tabler/icons` and are served by the consumer. They are not the kit's, so they never go through the policy (ADR-0034: "only the SVG strings the kit ships with").
- Assumption: **fetched icons need a sink-free path in every browser.** A page can't tell whether Trusted Types are enforced. Any code path that must work "without Trusted Types" and isn't allowed to use a string-fed sink (requester: "no `parseFromString` with a plain string") must therefore also be safe under enforcement. That is why AC-12 asks for a sink-free path with an allow-list. If the designer finds no sink-free way to parse fetched SVG without a new dependency, they ask back before AC-12 is narrowed.
- Assumption: **minor, not major.** The only consumers who could lose icons are apps that enforce Trusted Types with a `trusted-types` allow-list that admits `angular#unsafe-bypass` but not `lc-icon`. That is one *Migration* line. No known consumer is affected:
  - the life-os app renders no icons today;
  - the life-os website sets no Trusted Types directive;
  - LC Factory used `@life-cockpit/angular-ui-kit`, which stops at 3.2.x.
- Assumption: **`activeRoute` is the source of truth when it is set.** It has been documented that way since 3.3.0 ("the one whose `route` equals `activeRoute` gets `aria-current="page"`"), and it matches `lc-bottom-nav`. As a consequence, a router-matched ancestor no longer looks current while `activeRoute` names another link. That edge case goes under *Changed*.
- Assumption: **life-os's 150 kB is checked in life-os** (T319). The kit proves its part with a fixture (AC-17, AC-18). How many entry points there are, and how they are grouped, is the designer's decision within AC-15 and AC-16.
- Assumption: **`busy` only sets `aria-busy`.** No visual change and no built-in text.
- Assumption: **one release, as requested** (3.5.0). The release-manager replies to `life-os-d4 [fc8635]` by its ref with the version and the CSP line.
